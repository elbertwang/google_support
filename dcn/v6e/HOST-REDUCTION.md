# The fused all-reduce is slow because the sum runs on the host CPU

```bash
export LIBTPU_INIT_ARGS="--xla_tpu_use_megascale_host_reduction=false"
```

**+54% on `jax.lax.psum` over DCN.** Stock `libtpu 0.0.44`, no custom binary, no
graph change.

Measured on tpu7x (2 × `tpu7x-standard-4t`, DP=2, dim 32768, warmups 200,
reps 10, best-of). `exchange_add` — the same reduction written as
`v + ppermute(v)`, which goes down a different transport path — rides along in
every run as an in-process control.

```
                     psum                              exchange_add (control)
default      161.1  159.1  166.1  → 162.1 ± 3.6        287.8 ± 10.9
flag=false   245.5  242.9  260.8  → 249.7 ± 9.6        277.5 ± 15.0
                                     +54.0%              -3.6%
```

Welch t ≈ 14.8. The control does not move, so this is not machine drift.

`psum` goes from **56% of `exchange_add` to 90%**, and from 43% to 66% of the
379.2 Gbps bidirectional raw-TCP ceiling measured with neper on the same NICs.

## Why

The flag does not change scheduling. It changes **how `psum` is lowered**.

| | default (`=true`) | `=false` |
|---|---|---|
| megascale transfer type | one `ALL_REDUCE` | `ALL_TO_ALL` + `ALL_GATHER` |
| `add`/`reduce` instructions in HLO | **0** | **3** |
| where the sum executes | host CPU / DRAM | TPU HBM |
| transport semantics | fused reduction | pure DMA |

By default the SUM is folded into the host transfer. That is why the HLO for a
DCN all-reduce contains **no add instruction at all** — the reduction is not in
the graph, it is inside libtpu on the host. Data is pulled into host DRAM, summed
by CPU threads, and pushed back. Host memory bandwidth becomes the limit while
the DCN link still has half its capacity free.

With the flag off, XLA emits reduce-scatter (as `ALL_TO_ALL`) + all-gather. Both
are pure DMA, and the add happens on the TPU against HBM bandwidth.

Read the HLO in `after_optimizations_before_buffer_assignment`, not
`after_optimizations` — control dependencies are absorbed by scheduling before
the latter.

## This is what the hand-written ring was really doing

[`MANUAL-AR.md`](MANUAL-AR.md) reports a hand-written ring beating `psum` by
+66.4% at DP=2, +59.7% at DP=4, +37.9% at DP=8, +51.6% at DP=10. That advantage
was never about the ring algorithm. The ring is built from `ppermute`, which is
pure DMA, so it was **bypassing host reduction** — exactly what this flag does,
except the flag lets the compiler do it.

So the objection we heard from users — *"the gradient all-reduce is generated by
JAX, hand-writing a ring is not meaningful"* — is correct, and it no longer
matters. You do not need to rewrite the graph. You need one flag.

It also resolves a result that never fit: `psum_scatter` + `all_gather`
(`rs_ag` in `manual_ar.py`) measured **-21%** at DP=2, even though it decomposes
the all-reduce the "right" way. `psum_scatter` lowers to a fused
`REDUCE_SCATTER` transfer, which **also** runs host reduction. Decomposing the
collective is not the point; getting the sum off the host is.

## Three other flags from the same batch

Screened on top of the patched libtpu (baseline `psum` 164.7 ± 3.2):

| flag | psum | verdict |
|---|---|---|
| `--xla_tpu_use_megascale_host_reduction=false` | 267.6 | **+62.5%, works** |
| `--megascale_compute_engine_use_executor_for_grpc=false` | 165.3 | +0.4%, no effect |
| both together | 244.0 | **worse than host-reduction alone** |
| `--megascale_compression_threshold=0` + e5m2 quantization | crash | peer worker reports an unrecoverable error, coordinator aborts |

Do not ship `compute_engine_use_executor_for_grpc=false`. It exists to decouple
the Eigen summation threads from the gRPC thread pool — but once host reduction
is off there is no Eigen summation on the host, so it has nothing to decouple and
only fragments the thread pool. The two flags are in direct conflict: stacked,
`psum` drops 267.6 → 244.0 and the control drops with it (285.7 → 248.7),
i.e. it degrades the whole transport.

The FP8 arm crashes reproducibly. The failing worker is the peer and its Pod is
gone before its log can be read, so the root cause is not captured. It also has a
real numerical cost — `e5m2` has 2 mantissa bits — so enabling it for gradient
all-reduce is an accuracy decision, not free bandwidth.

## It does not stack with the gRPC combo

[`results/tpu7x/FLOWCTRL.md`](results/tpu7x/FLOWCTRL.md) found the only flag
configuration that survived repetition — `num_channels=32` +
`dynamic_lb_max_outstanding_bytes=64Mi` + `dynamic_lb_min_outstanding_rpcs=128` +
`grpc_enable_rpc_receive_coalescing` — worth **+10.0%** on `psum`. Re-measured on
top of the host-reduction flag, 2 interleaved rounds:

```
                host_reduction=false      + gRPC combo
psum          243.5  252.1 → 247.8      252.2  253.2 → 252.7    +2.0%
exchange_add  266.7  261.4 → 264.1      266.3  247.6 → 257.0    -2.7%
```

**+10% collapses to +2%, inside the noise** — the host-reduction arm's own second
sample (252.1) already matches both combo samples. Most of what the combo bought
was compensating for host reduction. Ship the one flag, not five.

(The combo does still have a tighter spread, as `FLOWCTRL.md` observed. Not worth
four extra flags for 2%.)

## What this invalidates

**Every negative flag result in this branch was measured with host reduction on**,
i.e. against a system whose real bottleneck was somewhere else. Tuning a
transport that is not the limit produces no signal. 46 flags were screened that
way. Those null results should be re-run now that the transport is actually
exposed (247.8 / 379.2 = 65% of the raw-TCP ceiling) — but note the combo above
is the cautionary example in the other direction: things that helped before may
not help now.

Unaffected, because they do not go through this lowering path: the neper raw-TCP
ceiling of 379.2 Gbps; the 50/50 split across both NICs with RX/TX = 1.00;
Chaotic Good being on by default and 4.8x worse when disabled; the
warmups ≥ 200 methodology.

Needs re-examination: `transport_numa_node` was judged a pessimization, but that
conclusion was about thread affinity for the Eigen summation on the host. There
is no summation on the host any more.

## Why 46 flags of black-box screening missed this

Three reasons, and the third is the interesting one.

1. The public XLA flags doc we worked from contains **zero** megascale flags —
   it covers performance/debugging/sparsecore, a different family entirely.
2. Our candidates were generated by guessing over the `megascale_*` prefix. This
   flag is `xla_tpu_*`. It lives at the XLA → MegaScale lowering boundary, not in
   the MegaScale runtime.
3. **We tested the semantically correct flag and it was a dead switch.**

```
--megascale_use_top_level_all_gather_and_local_reduction_for_ar=true
  164.3 Gbps    vs    baseline 163.1
```

That name reads as *"use top-level all-gather and local reduction for AR"* —
precisely the mechanism that eventually worked. It moved nothing, and on that
evidence we discarded the whole "get the reduction off the host" line of enquiry.
A false negative that killed the correct hypothesis.

That is the ceiling of black-box flag screening: it cannot distinguish *"this
flag has no effect"* from *"this flag is dead code"*. Only reading the lowering
source can. Credit for finding this one goes to a line-by-line review of
`LowerAllReduceWithShuffle`.

## Before you turn it on in production

Measured here: DP=2 only, microbenchmark only.

1. **Larger DP is unmeasured.** The replacement path is reduce-scatter +
   all-gather, which should scale at least as well, but that is theory.
2. **End-to-end gain will be smaller than 54%.** This is a pure-communication
   microbenchmark; in a real step the all-reduce overlaps with compute.
3. **Interaction with MaxText's default flags** (`xla_tpu_overlap_compute_collective_tc=true`
   and friends) is unmeasured.
4. **HBM pressure.** Moving the add onto the TPU costs HBM bandwidth and one
   temporary buffer. Fine at dim 32768; check it at your real shard size.

Numerical correctness is verified: `manual_ar.py`'s `verify()` checksums every
variant against `psum` to 1e-3, and passes with the flag on.
